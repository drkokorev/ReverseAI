# Веб-консоль ReverseAI — отчёт о сборке (2026-10-22)

Дизайн: [`docs/superpowers/specs/2026-10-22-web-console-design.md`](../specs/2026-10-22-web-console-design.md). Визуальный ориентир — макеты `Main`, `Release`, `Parity` (артефакт основателя). Снимки готовых страниц в обеих темах: [`docs/console-screenshots/`](../../console-screenshots/).

## Что сделано

Команда `reverseai console` запускает серверную веб-консоль (FastAPI + Jinja2, один CSS и один JS, без сборки фронтенда) поверх тех же функций конвейера, что и CLI. Код — `src/reverseai/console/`:

| Модуль | Ответственность |
|---|---|
| `app.py` | фабрика приложения `create_app(...)`, обработчики ошибок, подключение middleware |
| `context.py` | состояние процесса (реестр проектов, задачи, кэш артефактов, CSRF-токен) и рабочая фабрика шлюза LLM |
| `registry.py` | проекты каталога; `Project` читается с диска на каждый запрос и задачу (после финального ревью) |
| `jobs.py` | фоновые задачи: поток на задачу, одна активная задача на проект, русские сообщения, вычищение ключей |
| `actions.py` | действия этапов: те же вызовы и строки вывода, что у команд CLI; синхронное согласование |
| `roles.py` | роли согласующего и единственное место их отображения в `Approval` |
| `forms.py` | форма нового проекта → `ProjectCard`, русские тексты отказов юридического фильтра |
| `security.py` | проверка loopback, заголовки безопасности (CSP), вход по токену, CSRF |
| `artifacts.py`, `evidence.py` | кэшированное чтение артефактов (`Zone.VERIFIER`), файлы пакета доказательств |
| `read/` | модели страниц: список проектов, обзор, согласование, паритет, расходы |
| `routes/` | маршруты по страницам и действиям |
| `templates/`, `static/` | шаблоны страниц, `console.css` (токены тем), `console.js` |

Общие для CLI и консоли русские подписи этапов и сообщения об ошибках вынесены из `cli.py` в `src/reverseai/messages.py`.

## Страницы

- **Проекты** (`/`) — все проекты каталога: название, клон, режим, хост цели, отметка песочницы, полоса из 9 этапов, последняя активность. Кнопка «Новый проект».
- **Новый проект** (`/projects/new`) — все поля карточки: название, режим, продукт клона, бренд, адрес цели, разрешённые домены, песочница, юрисдикции политики данных, юрисдикция проекта, аттестация. Отказы юридического фильтра — по-русски рядом с формой, введённые значения сохраняются. Создание проекта логирует то же, что `reverseai init`.
- **Обзор проекта** (`/projects/<имя>`) — траектория 9 этапов (время завершения и итог каждого, зона), показатели (паритет, критичные, сходство кода с порогом, стоимость LLM), панель задачи (статус, время начала и конца, хвост вывода; страница опрашивает статус и перезагружается по завершении), запуск этапов (наблюдение с числом страниц, отправкой форм и зондированием; оракул; спецификация; подготовка выпуска; реализация и паритет с числом раундов и «нестабильным прогоном»; аудит), зоны с числом артефактов, журнал происхождения (последние 50 событий, `?all=1` — все, фильтр по префиксу типа, короткие хэши) и его целостность.
- **Согласование** (`/projects/<имя>/release`) — вкладки «Спецификация» (обзор, функции, правила, сущности, API, пробелы), «Сценарии» (метод, путь, тело, ожидания, критичность), «Очистка» (находки санитайзера, удержанные значения, отброшенные оракулом). SHA-256 пакета и путь к черновику. Форма согласования: подписант, роль (оператор платформы / аналитик заказчика), флажок подтверждения, кнопка → `run_release` с `Approval(package_sha256=<хэш показанного черновика>)`. После выпуска — «Выпущено», время, подписант, роль.
- **Паритет** (`/projects/<имя>/parity`) — вердикт порога, доля пройденных и критичных, нестабильные, раунды, таблица сценариев (оригинал/клон, расхождения), удержанные значения, шкала сходства кода с порогом, упоминания бренда, состав пакета доказательств, скачивание архива, предупреждение о неизолированной песочнице, «не является юридическим заключением».
- **Расходы** (`/projects/<имя>/costs`) — вызовы и стоимость LLM по ролям и моделям; числа совпадают с `reverseai costs` (проверено тестом).

Темы: тёмная и светлая на токенах из дизайна, по умолчанию — по `prefers-color-scheme`, переключатель в шапке, выбор в `localStorage` (в try/catch). На ширине телефона шапка переносится, таблицы и траектория прокручиваются внутри своих блоков, горизонтальной прокрутки страницы нет (проверено в браузерном тесте на 375 px).

## Как запустить

```bash
uv sync
uv run reverseai console --projects-root projects/ --operator "Даниил Кокорев"
# http://127.0.0.1:8765
```

Для этапа «Спецификация» и сборки нужны ключи провайдеров в окружении (`ANTHROPIC_API_KEY` и др.); без них консоль сообщает об этом по-русски и не вызывает модель. Не на loopback-адресе нужен `REVERSEAI_CONSOLE_TOKEN`, вход — форма `/login` (POST) или `Authorization: Bearer`.

Тесты: `uv run pytest -q tests/console` (TestClient на настоящем проекте, собранном конвейером со сценарной моделью вместо LLM), `uv run pytest -q -m browser tests/console` (Playwright). Снимки страниц: `CONSOLE_SCREENSHOTS_DIR=docs/console-screenshots uv run pytest -q -m browser tests/console/test_browser_smoke.py`.

## Отступления от дизайна и почему

1. **`src/reverseai/messages.py` вне `console/`.** Чтобы консоль и CLI говорили одинаковыми словами, подписи этапов и разбор ошибок вынесены из `cli.py` в общий модуль; поведение CLI не изменилось (его тесты прошли).
2. **Роль аналитика заказчика.** После переименования в `barrier/release.py` (D-010) консоль записывает роли как есть: `operator` и `customer_analyst` (`roles.approval_role` — тождественное отображение). Согласования, записанные до D-010 с ролью `customer_lawyer`, показываются как «юрист заказчика (до D-010)».
3. **Повторное согласование уже выпущенного пакета из консоли запрещено** (CLI это позволяет): повторный выпуск сбросил бы реализацию, паритет и аудит. Чтобы выпустить новый пакет, нужно заново подготовить выпуск. Записано в D-011.
4. **Пакет доказательств — в `<проект>/evidence/`.** У CLI каталог задаётся `--out`; в консоли он фиксирован, чтобы страница паритета могла его найти. D-011.
5. **Упоминания бренда на странице паритета** пересчитываются по артефакту кода клона и текущим брендовым словам карточки: аудит не сохраняет их отдельным артефактом (только в README пакета).
6. **Добавлено сверх дизайна:** проверка заголовка Host на loopback (защита от DNS rebinding); токен, если задан, требуется и на loopback; опция `--operator` (инициалы в шапке и подписант по умолчанию; без неё — «ОП»); пункты навигации «Обзор» и «Расходы»; вкладки согласования работают и без JS (`?tab=`).
7. **Шкала сходства — SVG**, а не блоки с inline-стилями: CSP запрещает inline-стили и скрипты.
8. **Согласование выполняется синхронно** (это быстрая операция), а не фоновой задачей; пока у проекта идёт задача, согласование отклоняется.
9. **Сборка в консоли не сбрасывает оригинал между сценариями** — как и CLI; для песочницы со сценариями записи нужен флажок «Разрешить нестабильный прогон» (аналог `--allow-unstable`).

## Известные ограничения

- Задачи живут в памяти процесса: после перезапуска консоли статус и вывод прошлой задачи не видны (результаты этапов — в проекте). Отменить запущенную задачу нельзя, только перезапуском консоли; блокировку проекта при этом снимает ядро.
- CLI и консоль могут работать с одним проектом одновременно: журнал и хранилище пишутся под файловыми блокировками (D-014), изменяющие операции упорядочены блокировкой проекта `pipeline.lock` (D-015). Параллельно две изменяющие операции над одним проектом не выполняются: вторая сразу получает отказ «проект занят другим процессом».
- Просмотр страниц пишет `artifact.read` в журнал (один раз на артефакт за запуск консоли) — по дизайну; в обзоре события `artifact.*` по умолчанию скрыты, но журнал всё равно растёт и от просмотров.
- Наблюдение через консоль в тестах проверено с подменой `pipeline.run_observe` (параметры формы); сам обход браузером покрыт существующим e2e CLI.
- `DockerSandbox` в консоли не подключён, как и в CLI: сборка идёт в `LocalSandbox` с предупреждением.
- Шрифты загружаются с Google Fonts; без сети используются системные.
- На снимках в `docs/console-screenshots/` видны временные пути pytest и порт тестовой цели — это тестовые данные.
- Многопользовательский режим, редактирование спецификации, websockets, портал заказчика — вне объёма этой версии (non-goals дизайна).

## Исправления после финального ревью

Замечания: `.superpowers/sdd/2026-10-20-foundation-and-web-pipeline/overnight-findings.md`. Каждое исправление — отдельный коммит с регрессионным тестом (сначала падающим). Итог: `uv run pytest -q` — 616 passed, 5 skipped; `uv run pytest -q -m browser tests/e2e tests/console` — 7 passed, 1 skipped (live-тест без `ANTHROPIC_API_KEY`); `uv run ruff check src tests` — чисто. Снимки в `docs/console-screenshots/` пересняты.

### Важные

- **I-1. Карточка проекта кэшировалась на всё время работы сервера.** Теперь `ProjectRegistry.get` читает `Project` с диска на каждый запрос и задачу (`src/reverseai/console/registry.py:58`); несколько экземпляров безопасны по D-014. Тест: `tests/console/test_registry.py::test_card_edits_after_start_apply_to_console_jobs_like_the_cli` (новый бренд в `card.json` после старта консоли маскируется при подготовке выпуска, хэш пакета совпадает с CLI); из `tests/console/test_parity.py` убран обход через `forget`.
- **I-2. Повреждённый проект давал английскую 500.** `ProjectInvalid` с русской причиной для карточки и `state.json` (`registry.py:26`, `registry.py:58`); список проектов показывает такой проект строкой «карточка повреждена: …» / «состояние конвейера повреждено: …» (`src/reverseai/console/read/projects.py:55-68`, `templates/projects.html`); его страницы — русская страница ошибки (`src/reverseai/console/app.py:74`); `RequestValidationError` — русская 400 (`app.py:79`); любое необработанное исключение — русская 500 с заголовками безопасности (`ErrorPageMiddleware`, `src/reverseai/console/security.py:100`, подключение `app.py:97`). Тесты: `tests/console/test_registry.py::test_projects_list_survives_a_broken_card`, `…_survives_a_corrupt_state`, `test_broken_project_pages_are_a_russian_error`, `test_unexpected_errors_render_a_russian_500`, `test_request_validation_errors_render_a_russian_page`.
- **I-3. `body_warning` показывался сырым токеном и считался находкой.** Подпись «предупреждение (тело запроса)» (`src/reverseai/console/read/release.py:21`), находки и предупреждения разделены (`read/release.py:45-58`), отдельный счётчик и блок «Предупреждения» с пояснением, как в markdown черновика (`templates/release.html:140`). Тест: `tests/console/test_release.py::test_body_warnings_are_labelled_and_counted_apart_from_findings`.
- **I-4. Не было блокировки проекта.** `project_lock` — неблокирующий `flock` на `<проект>/pipeline.lock`, при занятости `ProjectBusy` «проект занят другим процессом…» (`src/reverseai/project.py:34`, `project.py:46`). Её держат все изменяющие команды CLI (`src/reverseai/cli.py:72`, `_mutating`; `init` — на запись состояния), задачи консоли (`src/reverseai/console/actions.py:67`, `locked`; предварительная проверка до старта задачи — `actions.py:58`, `routes/phases.py:80`), согласование в консоли — проверка и выпуск под одной блокировкой (`actions.py:174`), создание проекта в консоли. `_complete` повторно проверяет предыдущий этап (`src/reverseai/pipeline.py:184`). Решение D-015 в `docs/spec/decisions.md` (ждёт подтверждения). Тесты: `tests/console/test_project_lock.py` (второй процесс держит блокировку → CLI-команды `observe`, `oracle`, `spec`, `prepare-release`, `approve`, `build`, `audit` выходят с кодом 1; задача консоли — 409 или проваленная задача с русским сообщением; согласование — 409; после снятия всё проходит), `tests/test_project.py::test_project_lock_refuses_a_second_holder_at_once`, `tests/test_pipeline.py::test_complete_rechecks_the_prerequisite`.

### Мелкие

- **M-1. Журнал в обзоре.** События `artifact.*` по умолчанию скрыты (чип «показать артефакты» / «скрыть артефакты», префикс `artifact.` тоже их показывает, строка «Скрыто событий artifact.*: N»), у каждой строки — колонка «Сводка» (этап, подписант и роль, `kind:name`, модель и стоимость, счётчики): `src/reverseai/console/read/overview.py:271` (`event_summary`), `overview.py:312` (`_listed`), `templates/project.html`, `routes/overview.py`. Чтения по-прежнему пишутся в журнал. Тесты: `tests/console/test_projects.py::test_overview_ledger_hides_artifact_events_by_default`, `test_overview_ledger_rows_carry_a_payload_summary`.
- **M-2. Устаревшая документация.** Строка D-011 (`docs/spec/decisions.md`), README (раздел «Веб-консоль»), этот отчёт (таблица модулей, отступление №2, известные ограничения), docstring `registry.py` описывают чтение проекта на каждый запрос, блокировки D-014/D-015 и роль `customer_analyst`.
- **M-3. Историческая роль.** `customer_lawyer` показывается как «юрист заказчика (до D-010)» (`src/reverseai/console/roles.py:22`). Тест: `tests/console/test_roles.py::test_role_labels_for_recorded_roles`.
- **M-4. Вход по токену.** Форма `/login` с POST и CSRF вместо `GET /login?token=…` (`src/reverseai/console/routes/auth.py:42`, шаблон `templates/login.html`); токен в адресе никого не впускает; публичны только `/login` и `/static/` (`security.py:48`); сервер `reverseai console` убирает строки запроса из журнала доступа (`RedactQueryFilter`, `security.py:87`; `cli.py:346`). Тесты: `tests/console/test_security.py::test_token_is_required_when_configured`, `test_token_in_the_url_does_not_log_in`, `test_login_form_needs_the_csrf_token`, `test_only_the_login_page_itself_is_public`, `test_access_log_drops_query_strings`; `tests/console/test_cli_console.py::test_serve_redacts_query_strings_in_the_access_log`.
- **M-5. Не-ASCII cookie.** Сравнение cookie как байтов UTF-8 (`security.py:82`). Тест: `tests/console/test_security.py::test_non_ascii_session_cookie_is_refused_not_a_crash`.
- **M-6. Русские сообщения.** Несовпадение хэша при согласовании — «черновик изменился — обновите страницу и проверьте пакет заново» (`actions.py:35`, `actions.py:187`; отказ по-прежнему пишется в журнал как `barrier.rejected`); `ledger-verify` печатает «Журнал цел: цепочка хэшей не нарушена, событий: N» (`cli.py:256`). Тесты: `tests/console/test_release.py::test_approve_with_a_stale_hash_is_rejected`, `tests/test_cli.py::test_cli_status_and_ledger_verify`.
- **M-7. Пакет доказательств вне консоли.** Пакет и сходство показываются и скачиваются, только если SHA-256 архива в `<проект>/evidence/` совпадает с последним событием `audit.evidence_pack` (`src/reverseai/console/evidence.py:54`, `read/parity.py:47`, `routes/parity.py:34`); иначе страница паритета, показатель в обзоре и скачивание сообщают, что пакет собран вне консоли. Тесты: `tests/console/test_parity.py::test_a_pack_built_outside_the_console_is_not_shown_as_current`, `test_the_console_pack_is_shown_when_it_matches_the_latest_audit`.
- **M-8. Ошибки валидации pydantic.** Одна русская строка «некорректные данные (Модель): поле — что не так; …; и ещё N», без многострочного английского текста и ссылок (`src/reverseai/messages.py:75`); то же в форме нового проекта. Тесты: `tests/test_messages.py`, `tests/console/test_jobs.py::test_validation_error_in_a_job_is_one_russian_line`.
- **M-9. Имена проектов в URL.** Все ссылки, действия форм, адрес опроса задачи и перенаправления строятся через `project_path` (percent-encoding, `src/reverseai/console/templating.py:48`). Тест: `tests/console/test_registry.py::test_project_names_are_url_encoded_in_links_and_redirects`.
- **Предупреждение Starlette** «Using `httpx` with `starlette.testclient` is deprecated» отфильтровано в `pyproject.toml` (`filterwarnings`, с комментарием): запасной путь через `httpx` работает, а `httpx2` — новая зависимость, которую не стоит добавлять ради тестов.

M-10 по договорённости не исправлялось и остаётся в списке известных ограничений.
